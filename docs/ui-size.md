# UI 크기 설정과 작은 화면 대응

## 목적

MDLogger는 QHD 모니터와 OS 배율 100% 환경뿐 아니라, FHD 노트북에서 OS 배율 150~200%를 사용하는 환경에서도 기록을 완료할 수 있어야 한다.

Qt는 OS 배율을 논리 픽셀로 변환한다. 따라서 FHD 1920×1080 화면은 Windows 배율에 따라 앱이 사용할 수 있는 논리 높이가 크게 줄어든다.

| 물리 해상도 | OS 배율 | 대략적인 논리 해상도 |
| ----------- | ------: | -------------------: |
| 2560×1440   |    100% |            2560×1440 |
| 1920×1080   |    125% |             1536×864 |
| 1920×1080   |    150% |             1280×720 |
| 1920×1080   |    200% |              960×540 |

메인 창의 기준 폭·높이는 420×680 논리 픽셀이다. 다만 상세 입력 화면과 검증 상태줄에 이 기준 높이보다 큰 공간이 필요하면, 앱은 시작할 때 그 최소 높이를 초기 높이로 사용한다. 이 높이는 현재 화면의 사용 가능 높이를 넘지 않으며, 결과 화면과 상세 입력 화면을 오가도 바뀌지 않는다. 작은 논리 화면에서는 특히 상세 입력 화면의 하단 확인 버튼이 잘리거나 접근하기 어려울 수 있다.

## 완료 상태

- 완료일: 2026-08-20
- 전역 UI 크기 설정과 다음 실행 시 적용 정책을 구현했다.
- 메인 창은 상세 입력과 검증 상태에 필요한 높이를 시작 시 한 번 결정하며, 결과·상세 입력 화면 전환에서는 크기를 바꾸지 않는다.
- 화면 높이가 부족한 경우에는 상세 입력 화면만 스크롤해 하단 확인 버튼 접근을 보장한다.
- 로그인 창은 메인 창과 별도 크기 정책을 유지한다.

## 확정된 제품 결정

### UI 크기 적용 시점

`UI 크기` 설정은 즉시 열린 창을 재배치하지 않는다. 선택값은 기기 로컬 설정에 저장되며 **다음 앱 실행부터 적용**된다.

이 정책을 선택한 이유는 실행 중 `100% → 75% → 100%`처럼 여러 번 변경할 때, 이미 정수 픽셀로 배치된 위젯을 비율로 다시 계산하면 반올림 오차가 누적될 수 있기 때문이다. 다음 실행 시에는 모든 요소를 동일한 100% 기준값에서 한 번만 계산하므로 이 문제가 없다.

설정 창에는 다음 안내를 표시한다.

> 버튼·글자·아이콘·간격 등 모든 UI 요소를 같은 비율로 조정합니다. 다음 앱 실행부터 적용됩니다.

### 지원 값

UI 크기 선택지는 다음과 같다.

- 75%
- 80%
- 90%
- 100%
- 110%
- 125%
- 150%

값은 `AppSettings.ui_scale`에 저장한다. 허용 범위는 0.75~1.5이다.

이전 버전의 `settings.json`에 남아 있는 `font_scale` 값은 `ui_scale`이 없을 때 호환하여 읽는다. 새 설정 파일은 `ui_scale`만 기록한다.

### 작은 화면의 처리 원칙

작은 화면에서 일부 화면이 창 높이보다 길어질 때, UI 크기 비율을 임의로 깨거나 하단 버튼을 잘라 내지 않는다. **스크롤을 허용**한다.

특히 상세 입력 화면은 많은 입력 요소를 포함하므로, 하단 확인 버튼을 항상 스크롤로 접근할 수 있어야 한다.

## 구현 구조

### 시작 시 전역 UI 스케일

관련 코드:

- `src/mdlogger/app.py`
- `src/mdlogger/app_settings.py`
- `src/mdlogger/ui/theme.py`
- `src/mdlogger/ui/settings_window.py`

앱은 창을 생성하기 전에 설정을 읽고 다음과 같이 테마를 적용한다.

```python
apply_theme(
    app,
    mode=settings.theme_mode,
    accent=settings.accent_color,
    ui_scale=settings.ui_scale,
)
```

`theme.py`의 `scaled()`와 `METRICS`는 100% 기준값에 현재 UI 배율을 곱한다. 따라서 명시적으로 지정한 창 크기, 최소/최대/fixed 크기, 버튼 높이, 아이콘 크기, 여백, 간격, QSS의 padding·border·radius가 같은 시작 배율을 사용한다.

### Qt 기본 메트릭

코드가 직접 지정하지 않은 Qt 기본 레이아웃 margin, 목록/콤보 항목, 체크박스 indicator, 스크롤바 등도 배율을 따라야 한다.

`theme.py`의 `_ScaledStyle(QProxyStyle)`는 Qt 스타일의 `pixelMetric()` 값을 시작 UI 배율로 조정한다. 이를 통해 기본 `QLayout` margin처럼 스타일이 제공하는 값도 함께 축소·확대한다.

### 글꼴과 아이콘

- `QApplication` 기본 글꼴은 시작 UI 배율로 설정한다.
- `font_for_role()`은 제목·섹션·숫자 같은 역할별 글꼴에 UI 배율을 적용한다.
- 버튼 아이콘은 `METRICS.icon_small`, `METRICS.icon_medium`, `METRICS.icon_large`를 사용한다.
- 현재 데스크톱 앱은 raw `QPixmap` 사진 위젯을 사용하지 않으며, SVG `QIcon` 크기는 UI 배율 대상이다.

### 명시적 창과 컨트롤 크기

다음 종류의 값은 모두 `scaled()` 또는 `METRICS`를 통해 지정한다.

- 메인 창, 설정 창, 통계 창, 계정/편집/관리 다이얼로그의 기본 및 최소 크기
- 설정 창 탐색 목록 폭
- 입력 컨트롤과 버튼의 최소 높이
- Stepper의 고정 버튼/라벨 크기
- 카드, 표 행, 테이블 헤더 최대 폭
- 레이아웃 margin, padding, spacing
- pyqtgraph 차트의 기본 크기, 선 굵기, 마커 크기

별도 관리자 앱도 시작 시 `SettingsRepository().load().ui_scale`을 적용한다.

## 메인 화면과 상세 입력 화면

### 화면 구조

메인 창의 중앙 위젯은 `QStackedWidget`이다.

```text
QStackedWidget
├── ResultView
└── QScrollArea
    └── DetailView
```

- `ResultView`는 스크롤 영역 안에 있지 않다.
- `DetailView`만 전용 `QScrollArea` 안에 있다.
- 결과 화면에서 상세 입력 화면으로 이동할 때 상세 스크롤 위치는 맨 위로 초기화한다.
- 메인 창은 표시 직후 네이티브 창 프레임 높이와 실제 화면을 한 번 다시 확인해 초기 높이를 보정한다. 이후 결과·상세 입력 화면 전환은 창 크기를 바꾸지 않는다.

### 이 구조가 필요한 이유

처음에는 `QScrollArea`가 결과·상세 두 페이지를 함께 가진 `QStackedWidget` 전체를 감쌌다.

```text
QScrollArea
└── QStackedWidget
    ├── ResultView
    └── DetailView
```

이 구조에서는 숨겨진 상세 입력 페이지의 큰 size hint가 결과 화면에도 영향을 줬다. 결과 화면 자체가 충분히 작아도 세로 스크롤바가 표시되는 문제가 발생했다.

현재 구조에서는 결과 화면이 기존처럼 직접 `QStackedWidget`에 표시되므로, 결과 화면에 상세 입력의 스크롤 범위가 전달되지 않는다. 메인 창은 시작할 때 상세 입력의 최소 높이를 반영하므로 화면이 충분한 환경에서는 상세 입력에도 스크롤바가 나타나지 않는다. 화면 높이가 부족할 때만 상세 입력 화면이 스크롤된다.

### 결과 버튼

결과 버튼 높이를 화면 가용 높이로 강제 제한하던 상한은 제거했다. 상한은 UI 크기 비율을 깨고, 큰 UI 크기에서 버튼이 같은 비율로 확대되지 않는 원인이었다.

현재는 버튼 자체도 UI 크기에 비례하며, 화면 높이가 부족한 경우 상세 입력과 마찬가지로 스크롤이 접근성을 보장한다.

## 통계 창

관련 코드: `src/mdlogger/ui/stats_window.py`

통계 창에는 다음 스케일 규칙을 적용한다.

- 기본 창 크기와 최소 폭
- 카드 grid breakpoint
- 기록 표의 행 높이
- 기록 표 헤더 최대 section 폭
- pyqtgraph `PlotWidget`의 `sizeHint()`와 `minimumSizeHint()`
- 차트 선 굵기와 마커 크기

카드 grid는 표시 후 실제 탭 폭이 확정된 뒤 한 번 더 재배치한다. 재배치 전에 기존 Grid 항목을 비워, 이전 열 수에서 남은 빈 행의 최소 높이가 새 배치에 영향을 주지 않게 한다.

## 검증 항목

### 자동 검증

다음 검증을 수행한다.

```sh
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest <관련 테스트>
uv run pytest
```

UI 크기 관련 자동 테스트는 다음을 검증한다.

- `ui_scale` 값 파싱, 저장, 기존 `font_scale` 호환 읽기
- UI 크기 선택이 현재 창을 변경하지 않고 다음 실행용으로 저장되는지
- 75% 시작 시 메인 창과 설정 창의 초기 geometry
- 75% 시작 시 기본 Qt 레이아웃 margin의 스케일
- 설정 탐색 목록 폭, 아이콘 크기, QSS control height
- 큰 화면에서 결과 → 상세 입력 → 결과 전환 뒤에도 메인 창 크기가 일정하고 상세 입력에 스크롤바가 없는지
- 작은 메인 창에서 확인 버튼까지 스크롤 가능한지, 상세 입력을 다시 열면 스크롤 위치가 맨 위로 초기화되는지
- 결과 화면이 상세 화면의 스크롤 범위를 상속하지 않는지
- 네이티브 창 프레임을 고려해 사용 가능 화면 높이를 다시 제한하는지
- 통계 창 카드 열 수와 테이블 header 제약의 스케일
- 기존 결과 → 상세 입력 → 저장/취소 클릭 흐름

### 알려진 전체 테스트 환경 실패

전체 테스트는 현재 작업 트리에 생성된 `src/mdlogger/remote/_bundled_config.py`가 존재하면 `tests/test_build_config.py`의 두 테스트가 실패한다. 이 테스트는 개발 소스 트리에 생성 파일이 없어야 한다고 기대한다.

이 실패는 UI 크기 변경과 무관하다. UI 관련 대상 테스트와 Ruff, 포맷, 타입 검사는 통과해야 한다.

## Windows 수동 검증 체크리스트

Qt의 offscreen 테스트는 Windows 비클라이언트 영역, 작업 표시줄, OS 네이티브 파일 선택기 동작을 완전히 재현하지 못한다. 릴리스 전 실제 환경에서 다음을 확인한다.

1. FHD 1920×1080, Windows 배율 150% 또는 200% 환경에서 UI 크기 75% 선택 후 앱을 완전히 종료하고 다시 실행한다.
2. 결과 화면에서 불필요한 세로 스크롤바가 없는지 확인한다.
3. 상세 입력 화면에서 다음 상태를 각각 확인한다.
    - 이벤트 점수 모드
    - 랭크 모드
    - 레이팅 모드
    - 메모 켬/끔
    - 변동폭 입력/직접 입력
4. 상세 입력 화면의 하단 확인 버튼까지 마우스 휠 또는 트랙패드로 스크롤 가능한지 확인한다.
5. UI 크기 75%, 100%, 125%를 각각 선택하고 매번 재시작한다.
6. 메인 창, 설정 창, 통계 창, 기록 표, 카드, 차트, 아이콘, 설정 탐색 목록의 비율이 일관적인지 확인한다.
7. 휴대용 아카이브 가져오기에서 열리는 OS 네이티브 파일/폴더 선택 창은 운영체제 DPI 정책을 따른다. 이 창의 외관은 앱 QSS로 완전히 제어할 수 없다.

## 변경 시 주의 사항

- 새 고정 UI 크기를 추가할 때 원시 픽셀 값을 직접 사용하지 않는다. `scaled()` 또는 `METRICS`를 사용한다.
- UI 크기 변경을 실행 중인 위젯에 ratio 방식으로 다시 적용하지 않는다.
- 결과 화면 전체를 `QScrollArea` 안에 넣지 않는다. 상세 입력 화면에만 스크롤 폴백을 둔다.
- 사용자 데이터 설정은 `MDLOGGER_DATA_DIR` 및 기존 `paths.py` 규칙을 유지한다.
- UI 문자열과 문서는 한국어를 literal Hangul로 작성한다.
