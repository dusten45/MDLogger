# MDLogger 미결 항목 (Open Items)

이 문서는 `docs/online-account-and-duel-data-roadmap.md` 의 단계별 구현 기록에서
**아직 진짜로 열려 있는 항목만** 모은 것이다.

분류 기준:

- **포함**: 어느 단계에서도 아직 끝나지 않았거나, 명시적으로 "후속 결정/후속 통합/추후"로
  미뤄져 현재까지 미해결인 항목.
- **제외**:
  - "다음 단계에서 하기로 계획된 순차 연기" 항목은 이미 이후 단계에서 완료됐으므로 제외한다
    (예: 단계 6의 게스트 import UI "준비 중" → 단계 9 완성, 단계 7의 pull → 단계 8 완료).
  - 아직 진행하지 않은 전체 단계(단계 11 운영·계정 관리, 단계 12 최종 통합·배포)는 이 문서의
    범위가 아니라 로드맵 본문에 있다. 다만 아래 "해소 예상 위치"에서 해당 단계로 연결한다.

각 항목은 "어느 단계에서 남았는지 → 무엇이 남았는지 → 현재 상태 → 어디에서 해소해야 하는지"
순으로 정리한다.

## 항목별 상세

### 1. Qt 자동 UI 클릭 테스트

- **최초 지적**: 단계 1 "남은 위험 및 단계 2 진입 전 주의점", 단계 6 완료 조건.
- **내용**: 실제 Qt 클릭·다이얼로그를 구동하는 자동 UI 테스트가 아직 없다. 핵심 저장/취소/편집
  흐름의 회귀 탐지력을 높이려면 추가가 권장된다.
- **현재 상태**: 미추가. 기존 검증은 offscreen smoke 테스트와 mock 기반 단위 테스트로 수행 중.
- **해소 예상 위치**: 단계 12에서 최종 통합 시 추가하거나, 그 전에 지속적으로 보강.

### 2. 도메인 DTO 도입 결정

- **최초 지적**: 단계 1 "남은 위험".
- **내용**: UI는 raw connection에서 분리됐지만 반환 행 타입이 여전히 `sqlite3.Row`다.
  온라인/다중 저장소 구현 전에 안정적인 도메인 DTO 도입 여부를 결정해야 한다는 항목.
- **현재 상태**: 온라인/동기화 구현(단계 4~8)이 진행됐음에도 DTO 도입 여부는 아직 결정되지 않았다.
- **해소 예상 위치**: 제품 결정 또는 단계 12 통합 시점.

### 3. 백업 보존 정책/개수

- **최초 지적**: 단계 2 "남은 위험 및 단계 3 이후 주의점".
- **내용**: migration 백업은 source schema version별 고정 이름으로 보존된다. 제품의 백업 보존
  개수와 사용자 노출/정리 정책이 배포 정책과 함께 확정되지 않았다.
- **현재 상태**: 미확정.
- **해소 예상 위치**: 단계 11의 운영 정책(백업/복구) 또는 단계 12.

### 4. Turnstile/CAPTCHA 게스트 남용 방어

- **최초 지적**: 단계 4, 5. `checkAbuseGuards` 확장 경계와 428 `challenge_required` 계약만
  확정하고 "나중에 넣을" 항목으로 남김.
- **현재 상태**: Edge Function/클라이언트에 확장 경계만 있고, 실제 Turnstile 검증과
  `challenge_token` 전달 로직은 미구현.
- **해소 예상 위치**: 단계 11의 남용 대응 절차 구성.

### 5. hosted production + Windows 패키징 검증

- **최초 지적**: 단계 5(Windows Credential Manager + hosted Supabase), 단계 7(Windows
  PyInstaller worker 종료), 단계 8(실제 물리 PC/Windows 패키징)에서 반복적으로 "후속 통합
  단계에 남아 있다"고 명시.
- **내용**:
  - 실제 hosted Supabase 적용(현재는 local Supabase + mock으로만 검증).
  - 실제 Windows Credential Manager 사용 확인(Linux Secret Service만 smoke test).
  - Windows PyInstaller 빌드에서 인증·secure storage·네트워크·worker 종료 검증.
  - 실제 서로 다른 물리 PC에서의 다중 장치 동기화.
  - macOS/Linux에서 secure storage와 경로 검증.
- **현재 상태**: 클라이언트 동작은 mock과 local Supabase 기반으로만 검증됨. hosted 적용과
  Windows 패키징 검증은 미수행.
- **해소 예상 위치**: 단계 12(실제 빌드·플랫폼·배포 검증).

### 6. 최종 Windows 시각적 폴리시

- **최초 지적**: 단계 6 "완료 조건 결과와 남은 위험".
- **내용**: 라이트/다크 대비, 125%/150% 스케일, 한국어 줄바꿈은 자동 검증했지만, 실제 Windows
  화면에서의 최종 시각적 폴리시는 사용자가 예고한 전체 UI 최종 점검에 남아 있다.
- **현재 상태**: 미수행(사용자 주도 전체 UI 점검 예정).
- **해소 예상 위치**: 단계 12 또는 사용자의 전체 UI 최종 점검.

### 7. tombstone 물리 정리·비활성 장치 제거

- **최초 지적**: 단계 8 "완료 조건 결과와 단계 9 진입 전 주의점".
- **내용**: tombstone의 물리 정리와 비활성 장치 제거를 명시적으로 "구현하지 않았다"고 남김.
- **현재 상태**: 미구현. (단계 7/8의 tombstone 보존·전파는 구현됨.)
- **해소 예상 위치**: 단계 11(보존·삭제 정책, 운영 기능).

## 단계 10에서 추가로 남은 항목

### 8. 휴대용 아카이브 UI 배선

- **최초 지적**: 단계 10 구현 기록(2026-08-09)의 "단계 11 진입 전 주의점".
- **내용**: 단계 10의 핵심(versioned portable archive writer/reader, manifest·NDJSON·checksum,
  크기·행 수·문자열·경로 검증, `import_batches` 중복 방지, cross-profile provenance, outbox
  등록)은 완료됐지만, **UI 배선(휴대용 내보내기 버튼 / import 대화상자)은 아직 안 된 상태**다.
- **현재 상태**: 모듈(`src/mdlogger/portable.py`)과 테스트만 있고 UI 연결 없음. `GameService`에
  내보내기 진입점만 추가됨.
- **해소 예상 위치**: 단계 11 또는 그 전에 UI 배선으로 해소. 단, 단계 2~9의 "준비 중 → 이후
  완성" 패턴(예: 게스트 import)과 동일하므로 계획된 순차 작업으로 볼 수 있다.

## 제외 항목(이미 해소됨, 참고용)

오해를 피하기 위해, "남은 위험"으로 기록됐지만 이후 단계에서 실제 해소된 항목들은 여기 정리한다.

- **게스트 import UI "준비 중"** → 단계 9에서 완성.
- **동기화 상태 표시(로컬 저장만)** → 단계 7에서 pending/failed/synced 반영.
- **push 후 pull/커서/충돌 없음** → 단계 8에서 구현.
- **`owner_id`/`profile_kind` 비움** → 단계 3에서 설정.
- **실제 인증·로그인 UI 없음** → 단계 5~6에서 구현.
- **게임 sync worker 없음** → 단계 7에서 구현.
