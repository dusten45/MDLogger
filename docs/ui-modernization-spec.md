### 2단계(P1) UI 관련 변경 (2026-08-10)

단계 0~11 외부 검토의 P1 항목 중 UI 수명주기·스레딩과 직접 관련된 변경을 반영했다.

- **UI 스레드 네트워크 I/O 제거 + 로컬 연산 직접 실행 (P1-5)**: `run_once`(네트워크 동기화)만 worker thread가 실행한다. 충돌 조회·해결(`list_conflicts`·`resolve_conflict`)과 outbox 재시도(`retry_failed`)는 로컬 SQLite 연산이라 네트워크와 무관하므로, worker가 느린 네트워크 사이클에 묶여도 UI가 블로킹되지 않도록 호출자(UI) thread에서 짧은 수명의 연결로 직접 실행한다(WAL + busy_timeout으로 동시성 안전). 실패는 호출부로 전파해 비모달 안내로 표시한다. 초기 상태는 I/O 없이 기본값으로 시작하고 첫 tick에서 worker가 실제 상태로 갱신한다.
- **창 수명주기 `deleteLater` (P1-10)**: 프로필 전환 시 닫히는 `MainWindow`/`StatsWindow`가 닫힌 `GameService` 참조를 들고 누적되지 않도록 `close_profile_windows`에서 `deleteLater()`를 예약한다. `tests/test_app_controller.py::test_profile_switch_schedules_window_deletion`으로 검증.
- **휴대용 아카이브 UI 배선 (P1-13)**: 아직 미배선. 휴대용 내보내기 버튼/import 대화상자는 하드닝 H-3로 **연기 확정**이며, 현재는 CSV/XLSX 내보내기를 대체 경로로 제공한다. 나중에 배선할 때는 `docs/online-account-and-duel-data-roadmap.md` §13 단계 12 "이번 릴리스 미루기 확정 항목"의 구현 포인트(호출 함수·대상 DB 경로·참고 테스트)를 참고한다.

### 계정·인증 UI 반영 (2026-08-11)

계정·인증·게스트 시나리오 구현이 완료됨에 따라 이전 "계정 기능 개발에 따른 일시 중단"은 해소되었다. 새로 추가된 계정 UI(`src/mdlogger/ui/account_views.py`)는 다음과 같다.

- `AuthWindow`: 로그인·회원가입·비밀번호 표시/숨김·Enter 제출·이메일 인증 안내/재전송·비밀번호 재설정 요청. 오류는 이메일/비밀번호/폼 수준에 배치하고 네트워크·자격 증명·이메일 미인증·서버 거부를 구분한다.
- `GuestNoticeDialog`: 첫 프로필 진입 전 한 번으로 게스트의 로컬 지속·자동 업로드·전송/제외 필드를 안내하고 동의 버전을 로컬에 저장한다.
- `GuestRecordChoiceDialog`: 게스트→등록 계정 로그인 시 원본 기록 수와 가져오기/보관/나중에 결정 선택을 제공한다. 원본 게스트 DB는 병합·서버 반영 확인 전 삭제하지 않는다.
- `AccountDialog`: 현재 프로필 상태, 지금 동기화, 충돌 해결, 로그인/다른 계정 전환, 로그아웃, 모든 기기 로그아웃, 내 데이터 내보내기, 계정 삭제를 제공한다. 로그아웃은 로그인 창으로 돌아가며 그곳에서 다시 로그인하거나 게스트로 계속할 수 있다(2026-08-13). 단일 기기 해제(장치 관리)는 2026-08-13에 제거했다.
- `ConflictDialog`: 3-way 병합 충돌 해결 화면.
- 결과 화면(`src/mdlogger/ui/result_view.py`): 계정/인증/오프라인/동기화 상태를 낮은 우선순위의 한 줄과 "계정" ghost 버튼으로 표시하고, 동기화 실패를 매 기록마다 모달로 표시하지 않는다. 상태 갱신은 `MainWindow.set_sync_coordinator`/`set_sync_status`가 `SyncCoordinator` 상태를 반영한다.

인증·고지·계정 화면은 `theme.py` semantic token과 역할 기반 스타일을 사용하며, 화면별 목표와 상태 표현 기준은 각각 §9.6·§12.1을 따른다.

### 단계 3 완료 (2026-08-12)

단계 3(통계·기록 관리 현대화)의 코드 구현과 자동 검증을 완료하고 상태를 확정했다.

- `src/mdlogger/ui/edit_dialog.py`: 필드 레이블(muted)·오류 상태(danger)·저장(primary)/취소(ghost) 버튼을 `theme.py` 토큰과 역할 기반 스타일로 전환했다.

### 단계 4 완료 (2026-08-12)

단계 4(아이콘과 미세 상호작용)의 공통 아이콘 기반과 첫 유니코드 아이콘 교체를 구현하고 상태를 확정했다.

- `src/mdlogger/ui/icons.py`를 추가했다. `importlib.resources`로 패키지 데이터(`ui/icons/`)의 단색 SVG를 읽고, `_ThemeIconEngine`(커스텀 `QIconEngine`)이 paint 시점에 `current_colors()`로 결정된 테마 색상으로 다시 칠한다. `QIcon.Mode`(normal/active/disabled)가 각각 `text_primary`/`accent`/`text_disabled` 토큰을 따르므로 라이트·다크와 disabled 상태가 모두 테마에 반응한다(실제 `QIcon.pixmap()` 호출로 라이트→다크 전환 시 색상 갱신을 검증).
- 번들 SVG 아이콘(`undo`/`minus`/`plus`)을 `src/mdlogger/ui/icons/`에 추가했다. 외부 아이콘 패키지 의존성은 추가하지 않았고, 단순한 원형 기하 아이콘을 직접 작성해 재배포 라이선스 이슈를 피했다.
- `src/mdlogger/ui/result_view.py`: 되돌리기 버튼의 유니코드 `↶`를 제거하고 "마지막 기록 취소" 텍스트 + 20px undo 아이콘으로 교체했다. 텍스트가 동작을 계속 설명하므로 아이콘 누락 시에도 의미가 유지된다.
- `src/mdlogger/ui/widgets.py`: `Stepper`의 −/＋를 16px 아이콘으로 교체하고, `accessibleName` + tooltip을 설정했다. SVG가 없으면 기존 −/＋ 텍스트로 fallback한다(§10 "아이콘 누락 시에도 텍스트로 동작을 이해할 수 있다").
- 패키징: hatchling wheel에 `ui/icons/*.svg` 포함을 확인했다. 소스 실행에서는 `importlib.resources`가 패키지 데이터를 읽는다. 단, PyInstaller는 `importlib.resources` 호출만으로 데이터를 수집하지 않으므로, 배포 빌드는 `MDLogger.spec`의 `collect_data_files("mdlogger")`로 `data/decks.json`과 `ui/icons/*.svg`를 명시적으로 번들한다(단계 5에서 오프라인 스모크로 확인). `tests/test_icons.py`가 소스 모드의 번들 로드·테마 리컬러·disabled/active 색상·fallback을 검증한다.
- 미세 상호작용: 기존 승/패 버튼의 hover 성장 애니메이션과 QSS 상태 표현이 이미 준수하므로(Quiet Utility, 입력 지연 금지) 새 애니메이션은 추가하지 않았다.
- 전체 테스트 기준선은 `333 passed / 2 skipped`(+7, 아이콘 테스트)로 갱신했다. 사전 존재하는 환경 관련 실패 1건(`test_startup_migrates_old_db_and_retains_backup`)은 단계 4 변경과 무관함을 clean 기준선에서 확인했다.

**완료 상태**: 단계 4 코드 구현과 자동 검증을 마쳤다. 실제 Windows/macOS/Ubuntu PyInstaller 빌드에서 아이콘 표시 확인은 단계 5(플랫폼 검증 및 패키징)에서 수행한다. 아이콘은 패키지 데이터로 포함되고 누락 시 텍스트 fallback이 동작하므로 완료 기준을 충족한다.

### 단계 5 완료 (2026-08-12)

단계 5(플랫폼 검증 및 패키징)의 코드 기반 패키징 수정과 Linux(현재 환경) 자동 검증을 수행하고 상태를 확정했다. 실제 Windows/macOS 화면 검증은 소유자 환경에서 수행해야 한다(아래 참고).

## 1. 목적

현재 기능과 데이터 동작을 유지하면서 MDLogger UI를 더 현대적이고 일관되며 읽기 쉽게 개선한다. 결과물은 Windows 11의 외관을 복제하는 앱이 아니라, Windows·macOS·Linux에서 동일한 제품 정체성을 유지하는 플랫폼 중립적인 데스크톱 앱이어야 한다.

이 문서는 다음 AI 에이전트가 추가적인 기술 선택 논의를 반복하지 않고 단계적으로 구현할 수 있도록 결정 사항, 작업 범위, 제약과 완료 조건을 정의한다.

### 1.1 제품 경험의 기준

MDLogger는 장시간 머무르는 대시보드가 아니라, 사용자가 게임 종료 직후 `Alt+Tab`으로 전환해 수 초 안에 결과를 기록하고 다시 게임으로 돌아가는 **키보드 우선의 빠른 입력 도구**다. UI 현대화는 이 핵심 상황을 모든 시각적 선택보다 우선한다.

사용 우선순위는 다음과 같다.

1. **기록:** 결과 선택 → 상세 입력 → 저장을 망설임 없이 완료한다.
2. **복구:** 잘못 고른 결과를 되돌리고 마지막 기록을 취소할 수 있다.
3. **검토:** 통계와 기록을 읽고, 필요한 행만 편집·삭제·내보낸다.

따라서 현대화의 기준은 장식의 양이 아니라 입력 속도, 상태 명확성, 오류 회복성, 장시간 사용 시 피로도다. `ui-ux-pro-max`의 자동 추천 중 글래스모피즘, 시네마틱 배경, 강한 glow, 장식적 모션, 외부 웹 폰트는 이 제품 맥락 및 Qt 데스크톱 제약과 맞지 않으므로 채택하지 않는다.

### 1.2 핵심 사용자 여정

```text
게임 종료
  → 앱 전환
  → 승/패 선택
  → 선후공·턴·덱·종료 방식·점수·메모 입력
  → 저장 완료를 즉시 확인
  → 다음 기록 대기 또는 통계 확인
```

- 첫 화면에서 승/패 선택 외의 요소가 주의를 빼앗지 않아야 한다.
- 상세 화면은 필수 입력을 먼저, 선택 입력을 나중에 읽히게 한다.
- 저장 실패 시 입력값을 잃지 않고 문제 필드와 해결 방법을 알려야 한다.
- 통계/기록 관리는 핵심 입력 흐름과 시각적으로 연결되지만 경쟁하지 않아야 한다.

## 2. 최종 기술 결정

### 2.1 채택

- PySide6를 유지한다.
- 현재의 Qt Widgets 구조를 유지한다.
- 공통 기반 스타일로 Qt `Fusion`을 우선 사용한다.
- 앱 전용 디자인 토큰과 역할 기반 스타일 시스템을 만든다.
- 창 프레임, 파일 다이얼로그, 키보드 동작, 텍스트 입력, 접근성 등은 Qt와 OS의 네이티브 동작을 유지한다.
- 라이트·다크 테마를 제공하며 기본값은 시스템 색상 체계를 따른다.
- 플랫폼별 차이는 꼭 필요한 동작에만 제한한다.

### 2.2 채택하지 않음

- Windows 전용 `windows11` 스타일을 공통 기본값으로 사용하지 않는다.
- Qt Quick의 `FluentWinUI3`를 공통 UI로 사용하지 않는다.
- QFluentWidgets를 추가하지 않는다.
- Electron, Tauri, 웹 프런트엔드 또는 C#/WinUI로 재작성하지 않는다.
- frameless window, 커스텀 타이틀바, Mica/Acrylic/blur 효과를 사용하지 않는다.
- 특정 OS 폰트 이름을 강제하지 않는다.

## 3. 결정 과정 요약

처음에는 Windows에서 오래된 프로그램처럼 보이는 문제를 해결하기 위해 Windows 11 스타일, QFluentWidgets, Qt Quick/QML의 FluentWinUI3를 검토했다.

코드 조사 결과 문제의 주원인은 PySide6가 아니라 다음과 같은 현재 스타일 구조로 판단했다.

- 모든 기본 위젯을 덮는 단순한 전역 QSS
- 여러 UI 파일에 분산된 하드코딩 색상과 인라인 QSS
- 기본 `QTabWidget`, `QTableWidget` 외관
- 라벨과 입력 필드가 반복되는 전형적인 세로 폼
- 아이콘과 명확한 Primary/Secondary 동작 계층 부족
- 시스템 다크 모드와 고대비 환경을 고려하지 않은 라이트 전용 색상

이후 프로젝트 목표가 Windows 전용이 아니라 다양한 OS 지원임을 재확인했다. 이에 따라 Windows Fluent 복제보다 공통 `Fusion` 기반의 앱 자체 디자인 시스템이 더 예측 가능하고 유지보수하기 좋은 방향이라고 결정했다.

## 4. 목표

1. 세 OS에서 화면 구조와 제품 정체성이 일관되어야 한다.
2. 기존 기록 입력 흐름과 데이터 동작을 보존해야 한다.
3. 라이트·다크 테마 모두에서 충분한 대비와 명확한 상태 표현을 제공해야 한다.
4. 고정 픽셀과 특정 폰트에 과도하게 의존하지 않고 DPI 및 폰트 차이를 견뎌야 한다.
5. 버튼의 중요도, 화면 섹션, 선택 상태와 오류 상태를 즉시 구분할 수 있어야 한다.
6. 스타일 값을 한곳에서 관리해 후속 변경 비용을 줄여야 한다.
7. 저장·삭제·내보내기·빈 데이터·오류 상태에 명확한 피드백을 제공해야 한다.

### 4.1 측정 가능한 UX 성공 기준

다음 항목은 구현 전 기준선을 기록하고 구현 후 같은 조건으로 다시 확인한다.

- 결과 선택은 마우스로 승/패를 **한 번의 명시적 입력**으로 선택할 수 있다.
- 상세 화면에서 일반적인 기록은 불필요한 모달 없이 저장할 수 있다.
- 버튼 입력에 대한 pressed/focus 피드백은 인지상 즉시 보이며, 장식적 전환이 입력을 지연하지 않는다.
- 저장 오류가 발생해도 사용자가 입력한 값은 유지되고 첫 번째 오류 필드로 포커스가 이동한다.
- `400×600` 전후의 기본 창과 Windows 125%·150% 배율에서 핵심 입력에 가로 스크롤이 생기지 않는다.
- 일반 텍스트 대비는 WCAG AA `4.5:1`, 큰 텍스트·UI 경계·포커스 표시는 최소 `3:1`을 목표로 한다.
- 승/패·선택·오류·그래프 계열은 색상 외에 텍스트, 아이콘, 선 모양 또는 위치 중 하나 이상으로 구분한다.
- 긴 한글/영문 덱 이름과 시스템 기본 글꼴 확대에서도 필수 동작의 레이블이 잘리지 않는다.

성공 기준을 맞추기 위해 새 기능이나 DB 질의를 추가하지 않는다. 측정 중 발견한 입력 흐름 변경은 별도 요구사항으로 분리한다.

### 6.2 확인된 문제

- `src/mdlogger/app.py`의 `APP_QSS`가 모든 `QPushButton`, `QLineEdit`, `QComboBox`를 전역으로 덮는다.
- `#f3f3f3`, `#c4c4c4`, `#1a1a1a`, `#555`, `#fafafa` 같은 라이트 테마 전용 색상이 여러 파일에 직접 작성되어 있다.
- `font-size: 13px`, `18px`, `40px` 같은 픽셀 단위 폰트가 플랫폼 폰트 및 배율 차이를 충분히 고려하지 않는다.
- 승패 버튼 hover에 웹 CSS의 `opacity`가 사용되어 Qt Style Sheet에서 의도대로 동작하지 않을 수 있다.
- `↶`, `↺`, `−` 같은 글꼴 의존 문자를 아이콘처럼 사용한다.
- 메인 창 기본 크기 `360×540`과 최소 폭 `340`은 Linux 폰트 또는 고배율 환경에서 여유가 부족할 수 있다.
- 상세 폼은 모든 필드가 같은 시각적 중요도로 세로 반복된다.
- 통계 화면은 5개 카드를 한 줄에 배치하고 기본 탭·라디오·테이블 스타일에 크게 의존한다.

## 7. 디자인 원칙

### 7.1 플랫폼 중립성

- Windows, macOS 또는 특정 Linux 데스크톱의 외관을 복제하지 않는다.
- OS별로 다른 위젯 트리를 만들지 않는다.
- `sys.platform` 분기는 메뉴, 단축키 또는 실제 플랫폼 동작 차이가 필요한 경우에만 사용한다.
- Windows 전용 시각 효과를 다른 OS에서 흉내 내지 않는다.

### 7.2 네이티브 동작 보존

다음은 직접 재구현하지 않는다.

- 창 제목 표시줄과 창 제어 버튼
- 텍스트 선택, 커서, 클립보드
- 키보드 포커스와 Tab 이동
- 파일 및 폴더 선택 다이얼로그
- 표준 메시지 다이얼로그
- 창 이동, 크기 변경, 전체 화면 처리
- 접근성 역할과 스크린 리더 연동

### 7.3 일관된 앱 디자인

- 배경, 표면, 경계, 텍스트, Accent, 성공, 실패 색상을 토큰으로 정의한다.
- 간격은 `4, 8, 12, 16, 24` 단계를 기본으로 한다.
- 모서리 반경은 작은 컨트롤 `8`, 카드 `12`를 기본으로 한다.
- 그림자보다 표면색과 경계를 사용해 섹션을 구분한다.
- 한 화면에 Primary 동작은 원칙적으로 하나만 둔다.
- 색상만으로 승패·오류·선택 상태를 전달하지 않고 텍스트 또는 형태를 함께 사용한다.

### 7.4 타이포그래피

- OS 시스템 기본 폰트 패밀리를 그대로 사용한다.
- `Segoe UI`, `San Francisco`, `Pretendard` 같은 폰트를 강제하지 않는다.
- 앱 기본 `QFont`의 point size를 기준으로 제목·본문·보조 텍스트 크기를 파생한다.
- 핵심 수치와 화면 제목만 굵게 표시한다.
- 한글 폰트 fallback과 긴 덱 이름을 고려한다.

### 7.5 Qt Style Sheet 사용 규칙

- 웹 CSS에만 존재하는 속성을 사용하지 않는다.
- 전역 타입 선택자보다 역할 속성 또는 `objectName` 선택자를 사용한다.
- 예: `QPushButton[role="primary"]`, `QLabel[tone="muted"]`.
- 상태가 자주 변하는 값은 QSS 문자열을 매번 새로 지정하지 말고 속성 또는 팔레트 기반으로 처리한다.
- ComboBox 팝업, 스크롤바와 복잡한 subcontrol은 꼭 필요한 경우가 아니면 과도하게 재스타일링하지 않는다.

### 7.6 시각 방향: Quiet Utility

채택할 스타일은 **Quiet Utility / Compact Productivity**다.

- 중립적인 배경과 또렷한 표면 계층을 사용하고 Accent는 선택·포커스·Primary 동작에 제한한다.
- 카드 남용을 피한다. 하나의 큰 표면 안에서 간격·섹션 제목·얇은 구분선으로 그룹을 만드는 것을 우선한다.
- 기본 그림자는 사용하지 않는다. 팝업·모달처럼 실제로 떠 있는 계층에만 Qt 기본 elevation 또는 매우 약한 그림자를 허용한다.
- gradient, glass, glow, 배경 이미지, 게임 HUD 모방, 과도한 둥근 모서리를 사용하지 않는다.
- 라이트를 기본적인 밝은 작업 환경으로, 다크를 동등한 기능의 저조도 작업 환경으로 설계한다. 다크를 더 “프리미엄”한 별도 제품처럼 만들지 않는다.
- 정보 밀도는 중간 이상으로 유지하되, 4/8 기반 여백과 최소 높이로 오입력을 방지한다.

### 7.7 상호작용 원칙

- hover는 보조 신호이며, 클릭 가능성과 선택 상태를 hover에만 의존하지 않는다.
- hover·pressed·checked·focus·disabled 상태는 서로 구분되며 레이아웃 크기를 바꾸지 않는다.
- 마우스/키보드 입력 피드백은 즉시 표시하고, 저장 중 중복 제출이 가능하다면 Primary 버튼을 잠시 비활성화한다.
- 화면 전환 애니메이션은 기본적으로 사용하지 않는다. 상태 변화가 갑작스러워 이해를 방해하는 경우에만 `100–180ms`의 짧은 색상/불투명도 전환을 검토한다.
- 애니메이션은 중단 가능해야 하며 포커스 이동, 클릭, 저장을 차단하지 않는다. OS의 reduced-motion 성향을 직접 안정적으로 감지하기 어렵다면 **모션 없음**을 안전한 기본값으로 둔다.
- 성공 피드백은 짧고 비차단적이어야 한다. 오류와 파괴적 작업은 사용자가 읽고 복구할 수 있을 때까지 유지한다.

### 8.5 토큰 체계

색상만 중앙화하지 말고 다음 토큰을 함께 정의한다. 토큰의 이름은 구현 중 조정할 수 있으나 의미 역할은 유지한다.

#### 색상

- 표면: `background`, `surface`, `surface-subtle`, `surface-raised`
- 텍스트: `text-primary`, `text-secondary`, `text-disabled`, `text-on-accent`
- 선: `border`, `border-strong`, `divider`, `focus-ring`
- 동작: `accent`, `accent-hover`, `accent-pressed`, `selection`
- 의미: `success`, `success-subtle`, `danger`, `danger-subtle`, `warning`, `warning-subtle`
- 그래프: `chart-axis`, `chart-grid`, `chart-primary`, `chart-secondary`, `chart-marker`

승리/패배는 `success`/`danger`와 연결할 수 있지만, 일반 Primary 동작을 승리색으로 만들지 않는다. 다크 테마는 라이트 값의 단순 반전이 아니라 각 foreground/background 조합을 별도로 검증한다.

#### 간격과 크기

- 간격: `4, 8, 12, 16, 24, 32`
- 작은 컨트롤 최소 높이: `32–36`
- 일반 입력/버튼 최소 높이: `36–40`
- 주요 동작 최소 높이: `44`
- 승패 선택 영역 최소 높이: `104`, 단 창 높이에 따라 자연스럽게 확장
- 아이콘 시각 크기: `16`, `20`, `24`; 클릭 영역은 텍스트 포함 최소 `36×36`
- 테두리: 기본 `1`, 포커스 링 `2`
- 반경: 작은 컨트롤 `6–8`, 섹션/카드 `10–12`; 같은 계층에서 임의 혼용 금지

숫자는 가능한 경우 tabular figure가 제공되는 시스템 폰트 기능을 사용하고, 지원 여부가 불명확하면 정렬과 고정 최소 폭으로 숫자 변화에 따른 흔들림을 줄인다.

#### 타이포그래피 역할

기본 `QFont`의 point size를 기준으로 파생한다.

- `display`: 결과 선택처럼 한 화면의 단일 핵심 표현, 기본 대비 약 `1.6–1.8배`
- `title`: 화면 제목, 약 `1.25–1.4배`, semibold/bold
- `section`: 섹션 제목, 약 `1.0–1.1배`, medium/semibold
- `body`: 기본 입력·본문, `1.0배`
- `label`: 필드 레이블, body와 같거나 약간 작게, medium
- `caption`: 보조 정보, 최소 가독 크기 이하로 축소하지 않음
- `numeric`: 카드 수치, title과 동일하거나 한 단계 크게, 정렬 안정성 우선

텍스트 역할은 raw point size를 위젯마다 지정하지 않고 `QFont` 헬퍼 또는 공통 위젯에서 적용한다.

- 하단 동작은 승패 선택보다 낮은 시각적 우선순위를 가져야 한다.
- 기존 signal과 기록 흐름은 바꾸지 않는다.
- 계정/인증/오프라인/동기화 상태는 낮은 우선순위의 한 줄과 계정 진입 버튼으로 표시하고, 색상만으로 상태를 전달하지 않는다. 상태 표시가 승/패 선택의 시각적 무게와 경쟁하지 않아야 한다.
- 최근 기록 표시가 새 DB 질의나 공개 API 변경을 크게 요구하면 1차 구현에서는 생략할 수 있다. 이 경우 기존 오늘 전적만 현대화한다.
- 창 제목 표시줄에 이미 앱 이름이 있으므로 본문에서 `MD Logger`를 크게 반복하지 않는다. 본문 상단은 오늘 전적과 현재 할 일에 사용한다.
- 승/패 버튼은 동일한 크기와 시각적 무게를 가지되 `승리 / WIN`, `패배 / LOSS`처럼 한글을 우선하고 보조 영문은 과도하게 강조하지 않는다.
- 각 버튼은 의미색의 강한 단색 면보다 `success-subtle`/`danger-subtle` 표면, 명확한 경계, 텍스트/아이콘 조합을 우선한다. 이 방식은 장시간 사용 피로와 다크 모드 채도를 줄인다.
- 오늘 전적은 `총전적`, `승`, `패`, `승률`을 모두 카드로 쪼개지 않는다. 한 개의 compact summary strip 안에서 숫자 정렬과 구분으로 표현한다.
- 마지막 기록 취소는 실제 취소 가능한 기록이 없을 때 disabled 이유를 tooltip 또는 보조 문구로 설명한다.
- 상세 화면 진입 시 첫 텍스트 입력(상대 덱 검색)에 포커스를 두고, 저장 오류 시 첫 오류 입력으로 포커스를 옮기는 동작을 테스트한다.

승/패 버튼 배치·동작 규칙(2026-08-11 소유자 실행 검토에서 정정된 사항):

- 버튼은 **세로:가로 = 4:3**(세로가 조금 더 길게) 고정 비율로, 가용 영역에 **contain-fit**(세로/가로 중 먼저 닿는 쪽 기준)으로 크기를 정한다. 단순히 세로만 늘리지 않는다.
- 버튼은 메인 창 하단의 `마지막 기록 취소` / `통계 기록` 줄 **바로 위**에 붙이고, 남는 공백은 버튼 **위쪽**(안내문과 버튼 사이)에 배치한다. 버튼 아래에는 공백을 두지 않는다.
- 두 버튼을 하나의 Expanding 레이아웃으로 묶어 세로를 채우면 **둘이 동시에 커지는 문제**가 생기므로, 각 버튼을 독립적으로 배치·크기 조절한다(호버된 버튼만 커진다).
- hover 성장은 **가로·세로 같은 비율**(전체적으로)로만 하며, 창을 벗어나거나 이웃 버튼을 침범하지 않는 범위로 제한한다.
- 텍스트·버튼 사이 공백은 **“줄인다”**지 “없애지” 않는다. 상세 입력 화면을 스크롤 없이 보여주려고 창을 크게 잡은 결과 메인 화면에 여분 공간이 생기면, 그 여백은 승/패 버튼과 그 위 텍스트 사이에 둔다.

요구사항:

- 관련 필드를 섹션 또는 논리적 행으로 묶는다.
- 선/후공과 소요 턴은 폭이 허용되면 같은 행에 배치한다.
- 너무 좁은 환경에서는 레이아웃이 잘리지 않도록 세로 배치로 fallback하거나 최소 폭을 현실적으로 지정한다.
- 결과는 화면 전체의 강한 색 배너보다 작은 상태 헤더 또는 배지로 표현한다.
- 확인 버튼은 유일한 Primary 버튼이다.
- 오류 메시지는 해당 입력 가까이에 표시하고 기본 상태에서는 불필요한 공간을 차지하지 않도록 한다.
- 기존 `DetailForm.values()`, `set_values()`, `reset()` 등 기능 API를 보존한다.
- `SingleSelect`, `SearchableDeckCombo`, `Stepper`, `Card`의 공개 동작을 보존한다.
- 시각적 읽기 순서를 `진행 정보 → 덱 → 종료 방식 → 점수 → 메모 → 저장`으로 맞춘다.
- 필수/선택 여부를 placeholder에만 맡기지 않는다. 레이블 또는 caption에 명시한다.
- 덱 자동완성은 입력 중 레이아웃을 밀지 않으며, 정확한 항목 선택 여부를 focus-out 또는 저장 시 검증한다.
- 점수 델타는 `+1,200`, `−800`, `변동 없음`처럼 부호와 텍스트를 제공해 색상 없이도 의미가 전달되게 한다.
- 유효성 오류는 원인과 해결 방법을 짧게 적고, 저장 시 첫 오류로 포커스를 이동한다. 오류가 해결되면 레이아웃이 크게 흔들리지 않도록 error 영역의 표시 방식을 통일한다.
- 결과 변경 동작은 ghost 버튼/링크 형태로 헤더에 두고, 저장 Primary와 떨어뜨린다.
- 저장은 명시적 확인 버튼으로 수행하며, 키보드 단축키나 `Enter` 기본 버튼에 의존하지 않는다.

## 9.5 화면 간 상태 및 입력 계약

- 이 프로그램은 **마우스(포인터) 중심**으로 조작하며, 키보드만으로 앱 전체를 조작하는 것은 지원하지 않는다(2026-08-11 소유자 결정). 결과/상세 화면의 액션 버튼(계정, 승/패, 마지막 기록 취소, 통계/기록, 결과 변경, 확인 등)에는 포커스 링을 표시하지 않는다.
- 텍스트 입력(덱 검색, 점수, 메모, 로그인 폼)은 타이핑을 위해 포커스를 받으며, 입력 순서는 시각적 위→아래, 좌→우 순서와 일치하도록 구성한다.
- `Esc`의 dialog 닫기처럼 명확한 개별 단축키는 유지한다. 전역 문자 단축키(`W`, `L` 등)는 텍스트 입력과 충돌할 수 있으므로 도입하지 않는다.
- 화면 전환 후 포커스는 새 화면의 첫 번째 텍스트 입력(상세 화면의 상대 덱 검색)에 둔다. 저장 오류 시 첫 번째 오류 입력으로 포커스를 옮긴다.
- 저장 성공 후에는 결과 선택 화면으로 돌아온 사실과 갱신된 오늘 전적이 즉시 보이는 것으로 완료 피드백을 제공한다. 별도 성공 modal은 사용하지 않는다.
- 저장 실패, DB 오류, 내보내기 오류는 blocking 여부에 맞춰 inline message 또는 표준 dialog를 사용하고 입력값/선택 상태를 보존한다.
- 통계 창은 독립 top-level window 동작을 유지하되 중복 창 생성, 포커스 유실, 메인 창 뒤에 숨는 문제를 검증한다.

## 10. 아이콘 정책

- 글꼴 문자를 아이콘으로 사용하는 부분은 단계적으로 SVG 아이콘으로 교체한다.
- 외부 아이콘 세트를 사용하면 라이선스를 확인하고 필요한 고지 파일을 추가한다.
- 외부 Python 아이콘 패키지를 의존성으로 추가하지 않는다.
- 아이콘 파일은 앱 패키지 안에 포함하고 PyInstaller 빌드에서 누락되지 않게 한다.
- 라이트·다크 테마 모두에서 보이도록 단색 SVG 또는 테마별 색상 적용 방식을 사용한다.
- 첫 구현에서 안전한 리소스 패키징 방법이 확정되지 않으면 아이콘 교체를 별도 단계로 분리하고, 텍스트 버튼을 유지한다. 기능을 아이콘만으로 표현하지 않는다.
- 한 아이콘 패밀리의 outline 스타일과 동일한 stroke 성격을 유지한다. Skill 검색 결과의 Phosphor는 시각 참고일 뿐 React 패키지를 추가하지 않으며, 실제 SVG 채택 전 라이선스와 재배포 조건을 확인한다.
- 아이콘 토큰은 `16/20/24` 세 단계로 제한하고 같은 위계에서 filled/outline을 혼용하지 않는다.
- SVG는 `currentColor`에 의존하는 웹 방식 대신 Qt 리소스·`QIcon`에서 라이트/다크 및 disabled 상태가 실제로 렌더링되는 방식을 작은 prototype으로 먼저 검증한다.

## 11. 반응형 및 DPI 요구사항

Qt Widgets에서 웹과 같은 완전한 반응형 UI를 목표로 하지 않지만 다음은 반드시 만족해야 한다.

- 고정 좌표 배치를 사용하지 않는다.
- 레이아웃과 `sizeHint()`를 우선한다.
- 긴 덱 이름이 버튼이나 창을 무제한 확장하지 않게 한다.
- 필요한 경우 elide와 tooltip을 함께 제공한다.
- 100%, 125%, 150%, 200% 배율에서 텍스트와 컨트롤이 겹치지 않아야 한다.
- 시스템 폰트가 Windows보다 큰 Linux 환경을 고려한다.
- macOS Retina에서 아이콘과 선이 흐릿하지 않아야 한다.
- 필수 입력 화면이 최소 창 크기에서 잘리면 `QScrollArea`를 검토하되, 불필요한 이중 스크롤은 만들지 않는다.
- 화면별로 layout mode는 가급적 두 단계만 둔다. 메인/상세는 compact와 regular, 통계는 narrow와 wide로 제한해 breakpoint 분기 폭증을 방지한다.
- breakpoint는 장치 이름이 아니라 `contentsRect()`의 실제 가용 폭과 `sizeHint()`로 결정한다. 시작 검토값은 상세 화면 `520`, 통계 화면 `760` logical px이며 실제 시스템 폰트 테스트 후 확정한다.
- compact 전환 시 정보와 동작을 숨기기보다 같은 행을 세로로 쌓는다. Primary 동작 위치와 읽기 순서는 유지한다.
- 레이아웃 모드 변경은 한 곳의 helper가 담당하고, 각 `resizeEvent`에서 불필요하게 위젯을 재생성하지 않는다.

## 12. 라이트·다크 및 접근성 요구사항

이 프로그램은 **마우스(포인터) 중심**으로 조작한다. 텍스트 입력은 타이핑을 위해 포커스를 받지만, 액션 버튼에는 포커스 링을 표시하지 않으며 키보드만으로 앱 전체를 조작하는 것은 지원하지 않는다(2026-08-11 소유자 결정).

- 기본 테마 모드는 시스템 설정이다.
- 시스템 색상 체계를 판별하지 못하면 라이트를 사용한다.
- 동작 중 시스템 테마가 바뀌면 가능한 경우 즉시 반영한다.
- 텍스트와 표면은 일반 텍스트 기준 충분한 대비를 유지한다.
- 색상만으로 승/패, 선택, 오류를 표현하지 않는다.
- Qt의 접근성 role을 방해하는 커스텀 페인팅을 피한다.
- Windows 고대비 또는 플랫폼 접근성 팔레트가 활성화된 경우 앱 고정 색상이 사용성을 심하게 떨어뜨리지 않는지 확인한다.
- `accessibleName`은 보이는 텍스트가 없는 제어와 의미가 불명확한 복합 위젯에 제공하고, `accessibleDescription`은 동작 결과나 입력 제약 설명이 필요한 경우에만 제공한다.
- 고대비 모드에서 앱 팔레트 강제가 OS 의미색을 훼손한다면 custom QSS 범위를 줄이고 시스템 `QPalette`를 우선하는 fallback을 둔다.
- tooltip만으로 필수 정보나 오류를 전달하지 않는다.

### 12.1 상태 표현 기준

| 상태             | 표현                                | 금지                            |
| ---------------- | ----------------------------------- | ------------------------------- |
| Hover            | 약한 표면/경계 변화                 | 클릭 가능성을 hover에만 의존    |
| Pressed          | 즉각적인 state layer 또는 경계 강조 | padding 변경으로 레이아웃 이동  |
| Focus            | 2px ring 또는 동등한 고대비 경계    | focus outline 제거 후 대체 없음 |
| Checked/Selected | indicator + 표면/텍스트 변화        | 색상만 변경                     |
| Disabled         | 낮은 강조 + 실제 disabled semantics | 흐리게만 보이고 클릭 가능       |
| Invalid          | 필드 경계 + 가까운 오류 문구        | 상단의 일반 오류만 표시         |
| Loading/Busy     | 동작 비활성화 + 짧은 진행 문구      | 응답 없는 것처럼 보이기         |
| Empty            | 원인 + 가능한 다음 행동             | 빈 표/빈 축만 표시              |
| Error            | 원인 + 복구 행동 + 상태 보존        | “오류”만 표시하거나 입력 초기화 |
| Success          | 갱신된 결과 또는 짧은 비차단 확인   | 매 기록마다 modal 표시          |

## 13. 플랫폼별 요구사항

### 13.1 Windows

- Windows 11에서 100%, 125%, 150% 배율을 확인한다.
- 기본 title bar를 유지한다.
- 고대비 모드에서 포커스와 텍스트를 확인한다.
- Windows 전용 스타일이나 blur 효과가 없어도 완성된 화면이어야 한다.

### 13.2 macOS

- 시스템 폰트를 유지한다.
- 기본 title bar와 창 제어 버튼을 유지한다.
- 표준 메뉴 및 단축키가 필요한 경우 Qt 표준 API를 사용한다.
- 파일 선택과 메시지 다이얼로그는 네이티브 동작을 우선한다.
- Apple Silicon과 Retina 환경에서 확인한다.
- Windows식 frameless title bar 또는 Fluent 효과를 추가하지 않는다.

### 13.3 Linux

지원 기준의 기본 환경은 Ubuntu LTS GNOME으로 둔다.

- Wayland 우선으로 확인한다.
- 가능하면 X11도 확인한다.
- 100%와 200% 배율을 확인한다.
- 시스템 테마 감지가 불명확해도 앱 라이트 테마로 정상 fallback해야 한다.
- KDE 등 모든 환경의 네이티브 외관을 복제하려 하지 않는다.

- [ ] 한 화면의 Primary 버튼은 하나뿐이다.
- [ ] 보이는 모든 클릭 요소에 hover, pressed, disabled 중 해당 상태가 정의되어 있다.
- [ ] pressed 상태가 padding/크기를 바꾸지 않아 주변 레이아웃이 흔들리지 않는다.
- [ ] 라이트·다크에서 본문 `4.5:1`, 큰 텍스트/경계/포커스 `3:1` 목표를 확인했다.
- [ ] 승/패·선택·오류·그래프 계열을 색상 없이도 식별할 수 있다.
- [ ] 아이콘 스타일·크기·stroke가 같은 위계에서 일관된다.
- [ ] 아이콘만 있는 동작에는 accessible name과 tooltip이 있다.
- [ ] placeholder가 레이블을 대신하지 않는다.
- [ ] 오류는 문제 필드 가까이에 원인과 해결 방법을 포함해 표시된다.
- [ ] 빈 화면·빈 표·빈 그래프에 설명과 다음 행동이 있다.
- [ ] 100%/125%/150% 및 큰 시스템 폰트에서 잘림·겹침·가로 스크롤이 없다.
- [ ] 긴 텍스트는 wrap 또는 elide + tooltip 정책을 일관되게 따른다.
- [ ] 그래프의 정확한 값이 hover에만 숨겨져 있지 않다.
- [ ] 모션이 입력·포커스·테스트를 차단하지 않으며 모션 없이도 의미가 유지된다.

## 16. 자동 검증

Python 코드를 변경한 각 단계에서 프로젝트 규칙에 따라 다음을 실행한다.

```bash
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest <관련 테스트 대상>
```

영향이 넓은 단계 2와 단계 3 이후에는 전체 테스트를 실행한다.

```bash
uv run pytest
```

Zed 에이전트 샌드박스에서 uv 캐시가 읽기 전용이면 프로젝트 `AGENTS.md`에 정의된 명령별 `/tmp` cache override를 사용한다. 이 override는 사용자 문서나 프로젝트 명령에 추가하지 않는다.

UI 자동 테스트를 추가할 때:

- signal과 public API를 우선 테스트한다.
- 픽셀 단위 스크린샷 비교만으로 기능을 검증하지 않는다.
- OS별 렌더링 차이가 있는 스크린샷 테스트는 플랫폼별 baseline을 분리한다.
- headless/offscreen 테스트가 실제 플랫폼 시각 검증을 대체한다고 간주하지 않는다.

## 17. 회귀 방지 요구사항

- `ResultView`, `DetailView`, `DetailForm`, `SingleSelect`, `SearchableDeckCombo`, `Stepper`, `Card`의 기존 public signal과 method는 가능한 한 유지한다.
- `AuthWindow`, `GuestNoticeDialog`, `GuestRecordChoiceDialog`, `AccountDialog`, `ConflictDialog`의 기존 public signal과 method를 유지한다. 게스트 원본 DB는 병합·서버 반영 확인 전 비파괴 방식으로 보존한다.
- DB 및 export API를 UI 미관 때문에 변경하지 않는다.
- `played_at` 로컬 naive ISO 형식을 유지한다.
- 사용자 데이터 디렉터리와 `MDLOGGER_DATA_DIR` 동작을 유지한다.
- 기존 비파괴 legacy-data migration을 유지한다.
- UI 코드에서 직접 DB 쿼리를 새로 추가하기 전에 기존 DB 함수를 확인한다.
- 관련 없는 리팩터링을 함께 수행하지 않는다.

## 18. 구현 중 판단 기준

다음 상황에서는 이 명세의 원칙을 기준으로 결정한다.

### 네이티브 외관과 공통 외관이 충돌할 때

공통 레이아웃과 접근성을 우선하고, 파일 다이얼로그나 창 동작처럼 OS 기대가 강한 부분만 네이티브를 우선한다.

### 더 현대적으로 보이기 위해 OS 전용 효과가 필요할 때

추가하지 않는다. 배경, 표면, 타이포그래피, 여백, 아이콘과 상태 계층으로 해결한다.

### QSS가 복잡해질 때

복잡한 subcontrol을 계속 덮기보다 기본 Qt 위젯 동작을 복원하거나 작은 공통 위젯 클래스로 책임을 이동한다.

### 외부 패키지를 추가하고 싶을 때

표준 PySide6 기능으로 해결 가능한지 먼저 확인한다. UI 테마 패키지는 기본적으로 추가하지 않는다. 꼭 필요하다면 라이선스, 세 OS 지원, PyInstaller 호환성과 유지보수 상태를 확인하고 별도 승인을 받는다.

### 플랫폼별 문제가 발생할 때

1. 레이아웃과 `sizeHint()` 문제인지 확인한다.
2. 시스템 폰트와 DPI 문제인지 확인한다.
3. QSS가 네이티브 동작을 덮었는지 확인한다.
4. 공통 해결이 불가능할 때만 최소 플랫폼 분기를 사용한다.

## 19. 최종 완료 정의

다음 조건을 모두 만족하면 UI 현대화 작업이 완료된 것으로 본다.

- PySide6 Qt Widgets 구조가 유지되어 있다.
- 외부 Fluent/UI 프레임워크 의존성이 없다.
- 스타일 토큰과 테마 적용이 중앙화되어 있다.
- 주요 UI 파일의 하드코딩 인라인 스타일이 제거되거나 명확한 예외만 남아 있다.
- 라이트·다크 테마가 동작한다.
- 메인, 상세, 통계, 기록 관리 화면의 시각적 계층이 명확하다.
- Quiet Utility 방향을 유지하며 glass/glow/장식적 gradient/과도한 카드가 없다.
- 마우스로 결과 선택 → 상세 입력 → 저장 흐름이 완료된다.
- 저장·오류·빈 데이터·선택 없음·삭제 상태가 명확하고 사용자 입력/선택을 불필요하게 잃지 않는다.
- 그래프는 앱 테마와 동기화되고 색상 외 구분 및 정확한 값 확인 수단을 제공한다.
- Windows, macOS, Ubuntu에서 핵심 기능이 검증되었다.
- 지원 DPI에서 텍스트 겹침과 심각한 잘림이 없다.
- 기존 데이터·통계·편집·삭제·내보내기 동작이 보존된다.
- Ruff, formatter, ty, 관련 테스트와 전체 테스트가 필요한 범위에서 통과한다.
- 플랫폼별 PyInstaller 빌드가 실행 가능하다.
- 로그인·동의·계정 화면이 라이트/다크·DPI에서 검증되었다.
- 계정·동기화 상태가 핵심 승/패 흐름보다 낮은 우선순위로, 색상 외 지표와 함께 전달된다.
